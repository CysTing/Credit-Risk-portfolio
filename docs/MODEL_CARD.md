# Model card

## Purpose and intended use

This is an educational portfolio project for exploring supervised classification, probability calibration, and model evaluation. It estimates a historical dataset's binary next-month credit card default label using prior financial histories. It is **not suitable for real credit approval, loan underwriting, pricing, collections, financial advice, or automated decisions about people**.

Intended users are students, educators, and portfolio reviewers. Interactive demonstrations must use fictional values. There is no customer data upload, identity collection, or production decision integration.

## Data

Source: I-Cheng Yeh, *Default of Credit Card Clients*, [UCI dataset 350](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients), [DOI](https://doi.org/10.24432/C55S3H), licensed CC BY 4.0. The original data has 30,000 credit card clients in Taiwan, with repayment, billing, and payment histories from April through September 2005. The response indicates default payment in the next month.

The derivative keeps 19 financial predictors and a binary `default` target. ID, sex, education, marital status, and age are excluded from the derivative and models. No customer identifier enters training. This is a data transformation, not a claim of anonymity, fairness, or absence of proxy variables.

UCI reports no missing values. Defensive imputers support software robustness; they do not establish validity under a new missingness process. Special repayment status codes are preserved as categories. Negative bill amounts are not automatically treated as errors because they can represent credits. See [the data dictionary](DATA_DICTIONARY.md) for unit and code caveats.

## Development protocol

| Component | Protocol |
|---|---|
| Split | Stratified random 60% train / 20% calibration / 20% test, seed 42 |
| Observations | 18,000 train; 6,000 calibration; 6,000 test |
| Preprocessing | Financial allowlist, guarded financial features, training-fitted imputation; scaling for logistic regression; categorical repayment encoding |
| Models | Logistic regression and bounded random forest, fixed reproducible parameters |
| Calibration | Sigmoid `CalibratedClassifierCV` around a frozen training-fitted estimator; calibrator fitted only on calibration split |
| Baseline | Training prevalence prediction, independent of test outcomes |
| Test role | Final descriptive comparison at a fixed threshold, plus explicitly exploratory interactive views |
| Persistence | Rebuild and cache models in memory; no external or user-uploaded pickle loading |

Exact hyperparameters live in `credit_risk/modeling.py` and are included in reproducible artifacts where available. No search for the best model or hyperparameters on test outcomes is performed. Both model families remain available, with no claim that one is universally best.

| Model | Fixed settings |
|---|---|
| Logistic regression | `C=1.0`, `solver="lbfgs"`, `max_iter=1500`, `random_state=42` |
| Random forest | `n_estimators=120`, `max_depth=10`, `min_samples_leaf=15`, `max_features=0.7`, `n_jobs=2`, `random_state=42`; default bootstrap sampling |
| Sigmoid calibration | Separate calibration set, frozen base estimator; no cross-fitting of the base estimator on calibration rows |

Each pipeline transforms 19 financial inputs into 18 numeric features (13 original amounts plus five engineered ratios) and six categorical status features. Explicit status categories `-2` through `9` produce 72 indicator columns, for 90 transformed features overall. Both pipelines use the same imputation, scaling, and categorical encoder; scaling is essential for the logistic model and harmless for tree splits.

A single random split is easy to inspect but has sampling variability. It is not external or temporal validation. If a viewer uses test plots to choose model settings or thresholds, another untouched dataset is required for an independent final estimate. Cost-based threshold exploration on the same calibration set used to fit the calibrator is optimistic and is shown only as an illustration.

## Evaluation

The app and training report compare raw and calibrated predictions. Metrics include ROC AUC, average precision, Brier score, log loss, and threshold-dependent accuracy, precision, recall, F1, and confusion counts. The prevalence baseline helps expose the limits of accuracy under class imbalance. Reliability bins show mean predicted risk against observed default fraction; their sample counts matter.

See `reports/` for results generated by `python scripts/train.py`. Values are descriptive results for this split, not guaranteed out-of-sample or future performance. Calibration is an empirical postprocessing method; it is not assumed to improve every score. Small reliability bins and sparsely supported fictional inputs are particularly uncertain.

Measured calibrated test results: logistic regression ROC AUC **0.7576**, average precision **0.5219**, Brier **0.13917**; random forest ROC AUC **0.7797**, average precision **0.5554**, Brier **0.13559**. Test prevalence is **22.1167%**. The raw forest Brier score is **0.13475**, so sigmoid calibration worsened its probability error on this test split. Both raw and calibrated outputs remain in the report.

Row identities are disjoint, but financial histories repeat. Using the 19 input values only (excluding the target), 78 unique histories occur in both training and test, covering 175 test rows; 54 occur in both calibration and test, covering 142 test rows. These row groups can overlap. This is not group-independent validation. The exact split and overlap evidence is saved in `reports/splits.json`.

## Explanations

Logistic feature contributions sum with the intercept to the **uncalibrated model's log-odds**. A sigmoid calibration layer changes the probability mapping; contribution bars must not be interpreted as additive percentage-point effects on calibrated risk.

Reference substitution recomputes a calibrated probability after replacing one input with its training-reference value: the median for amounts and the mode for categorical repayment status. It reports a local change relative to that particular reference, not a Shapley value or additive decomposition. It can create unrealistic feature combinations. A lower estimated probability is not evidence of a causal intervention.

Permutation importance evaluates model reliance by shuffling a feature in a bounded held-out sample and measuring the change in ROC AUC. Correlated variables can mask or share effects. Sampling variability can produce zero or negative estimates. Explanations are model behavior diagnostics, not causal explanations or legally sufficient credit decision reasons.

## Fairness and human impacts

No sensitive demographic attribute is used as a predictor or exposed in customer-facing inputs. That constraint does not remove structural inequality, protected-characteristic proxies, label bias, or selection bias. The bundled derivative intentionally cannot measure subgroup performance by the removed attributes. No fairness assessment or compliance claim is made.

Errors have asymmetric implications: a false negative misses a recorded default; a false positive flags an account that did not default. A demonstration threshold is not a policy recommendation. The project cannot assign appropriate economic or social costs, determine affordability, or justify a lending decision.

## Key limitations

- **Age and geography:** Taiwan 2005 credit card behavior may differ substantially from current borrowers, products, economies, and jurisdictions.
- **Selection:** existing account holders are not a representative sample of new loan applicants. Results do not generalize to people without repayment histories.
- **Target scope:** a binary next-month default indicator is not loss given default, exposure at default, expected credit loss, affordability, or lifetime loan default.
- **Ambiguous codes:** undocumented or special payment status values need cautious interpretation; categorical handling avoids inventing an ordering but cannot resolve meaning.
- **Random validation:** train, calibration, and test are from one historical snapshot. No future-period backtest or independent dataset is supplied.
- **Repeated histories:** identical financial-feature and target rows can remain after removing identifiers and demographic attributes. They are retained and may occur in different splits, creating another source of optimism. The app reports the duplicate count.
- **Calibration drift:** distribution or prevalence changes can invalidate calibrated probabilities. No live monitoring or automatic retraining exists.
- **Fictional inputs:** inputs inside permitted numeric ranges may still be improbable or outside the training distribution. A returned probability is not a guarantee of validity.
- **Statistical uncertainty:** one split and a finite test set do not yield individual uncertainty intervals. No formal probability confidence intervals are claimed.
- **Correlated financial variables:** coefficients and importance values can be unstable or misleading when interpreted individually.
- **Operational readiness:** production data contracts, security review, access control, audit trails, fairness governance, legal validation, and decision appeal processes are outside this project.

## Reproduction and maintenance

Use Python 3.12 with the pinned requirements, bundled financial-only CSV, and seed 42. Run `python scripts/train.py` to rebuild reports and `python -m pytest` after installing development requirements. Platform and numerical library differences can produce minor floating-point variation. Updates to data, feature definitions, library versions, or sampling protocol require reevaluation and a revised model card.
